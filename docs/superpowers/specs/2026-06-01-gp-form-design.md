**Date:** 2026-06-01

**Author:** brainstorming session

---

## Контекст

GP Form — публичная страница для Генерального подрядчика. ГП получает ссылку по email, открывает её в браузере без авторизации, вводит фактические объёмы по позициям BoQ за текущий период и отправляет данные. Позиции BoQ создаются стройконтролем при настройке объекта — ГП только заполняет объёмы.

После отправки период переходит в статус `gp_submitted` и передаётся стройконтролю на верификацию.

**Акцент:** `#d4824a` (терракота/янтарь)

**Разделители:** `#d8c4a8`  
**Шрифты:** EB Garamond (serif) для заголовков и названий, Space Mono для цифр и меток  
**Текстура:** subtle grain overlay (SVG feTurbulence, opacity 0.04)  
**Область применения:** desktop-only; мобильная адаптация — отдельный шаг

**Компоновка (C1 — Ledger):**  
Одностраничная форма с центрированным контейнером `max-width: 560px`. Каждая позиция BoQ — строка с горизонтальным разделителем: название + план слева, поле ввода + единица измерения справа. Имя подписанта и кнопка фиксированы в подвале формы.

## Маршрутизация

Новый **публичный** маршрут в `apps/web/src/main.tsx`:

## API

### Новый эндпоинт: GET /periods/gp/:token

Защищён `GpTokenGuard` (существующий guard). Возвращает данные для отображения формы:

```ts
{
  periodNumber: number
  objectName:   string
  gpTokenExpiresAt: string   // ISO 8601
  items: Array<{
    boqItemId:   number
    name:        string
    unit:        string
    planVolume:  number
  }>
}
```

**Ошибки (бросает GpTokenGuard):**
- `401 GP_TOKEN_INVALID` — токен не найден или истёк
- `403 GP_ALREADY_SUBMITTED` — данные уже поданы

**Реализация:** метод `getGpFormData(token: string)` в `PeriodService`. Читает `period` по `gpSubmissionToken`, включает связанные `boqItem` через `periodFact` → `boqItem`.

### Существующий эндпоинт: POST /periods/gp/submit/:token

Уже реализован. Принимает:

```ts
{
  gpSubmittedByName: string
  items: Array<{ boqItemId: number; gpVolume: number }>
}
```

## Компонент GpFormPage

Единый компонент, рендерит одно из пяти состояний по фазе:

```
useQuery(['gp-form', token], GET /periods/gp/:token)
├── isLoading          → <LoadingState>   (скелетон)
├── 401/403 INVALID    → <ExpiredState>   (ссылка недействительна)
├── 403 ALREADY_SUBMITTED → <AlreadySubmittedState>
└── success            → <FormState>
      └── после submit → <SuccessState>
```

**Состояния:**

| Состояние | Описание |
|---|---|
| `loading` | Скелетон строк таблицы |
| `form` | Основная форма ввода |
| `success` | Подтверждение: объект, период, подписант, дата |
| `expired` | Сообщение: ссылка истекла / невалидна |
| `already_submitted` | Сообщение: данные уже поданы + дата подачи |

## Валидация

**Правило:** кнопка «Отправить» `disabled` пока не выполнены оба условия:
1. Все N полей заполнены — `value.trim() !== ''` и значение парсится как число `≥ 0`
2. Поле подписанта непустое — `gpSubmittedByName.trim() !== ''`

**Важно:** `0` — валидное значение (работы за период не выполнялись).

**Поведение при попытке submit с ошибками** (если кнопка была нажата):
- Пустые строки получают класс `.error` — лёгкая красная подсветка фона (`#fde8e4`)
- Название работы подсвечивается красным
- Под названием появляется подпись «обязательно к заполнению»
- Прогресс-бар меняет цвет на красный
- Hint под кнопкой: «⊗ N позиций не заполнены»
- Кнопка остаётся `disabled`

**В чистом состоянии** (форма нетронута): никаких ошибок не показываем.

**Прогресс-бар:**
- `0%` → нейтральный (цвет разделителя)
- `1–99%` → терракотовый акцент
- `100%` → зелёный, текст «N из N ✓»
- При ошибках → красный

## Хук useGpForm.ts

```ts
function useGpForm(token: string) {
  const query = useQuery({
    queryKey: ['gp-form', token],
    queryFn: () => api.get(`/periods/gp/${token}`),
    retry: false,          // не ретраить 401/403
  })

  const mutation = useMutation({
    mutationFn: (data: SubmitPayload) =>
      api.post(`/periods/gp/submit/${token}`, data),
  })

  return { query, mutation }
}
```

Нет JWT-заголовка — запросы без `Authorization`.

## Ограничения и исключения

- ГП не может добавлять или удалять позиции BoQ — только заполняет объёмы по существующим
- Отправка однократная и необратима — повторная подача заблокирована на уровне API (`GP_ALREADY_SUBMITTED`)
- Черновики не сохраняются (localStorage не используется)
- Мобильная адаптация вынесена за рамки данного этапа
- Email-уведомление ГП со ссылкой реализуется в M-06 (NotificationService) — GP Form не отправляет email
