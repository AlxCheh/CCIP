**Формула `calcReadiness`:**
```
FOR EACH periodFact:
  factVol = acceptedVolume ?? scVolume ?? 0
  pct     = MIN(factVol / planVolume × 100, 100)
  total  += pct × weightCoef
RETURN ROUND(total, 2)
```

Items без `periodFact` строки вносят 0 (они не итерируются). `weightCoef = null` → пропустить.

  // ─── calcReadiness ───────────────────────────────────────────────────────────

  private async calcReadiness(
    periodId: number,
    tx: Prisma.TransactionClient,
  ): Promise<number> {
    const facts = await tx.periodFact.findMany({
      where: { periodId },
      select: {
        acceptedVolume: true,
        scVolume: true,
        boqItem: { select: { planVolume: true, weightCoef: true } },
      },
    });

    let readiness = 0;
    for (const f of facts) {
      const planVol = Number(f.boqItem.planVolume);
      if (planVol <= 0 || f.boqItem.weightCoef == null) continue;
      const factVol =
        f.acceptedVolume != null
          ? Number(f.acceptedVolume)
          : f.scVolume != null
          ? Number(f.scVolume)
          : 0;
      const pct = Math.min((factVol / planVol) * 100, 100);
      readiness += pct * Number(f.boqItem.weightCoef);
    }
    return Math.round(readiness * 100) / 100;
  }

### Sub-task 4b: Написать E-01/E-02/E-03

**Как работает period cycle для E тестов:**
1. `openPeriod(objectId, actorId)` → возвращает period с `gpSubmissionToken`
2. `submitGp(token, submitterName, [{boqItemId, gpVolume}])` → создаёт `periodFact` с `gpVolume`, статус → 'gp_submitted'
3. `upsertPeriodFact(periodId, boqItemId, scVolume: number, actorId)` → статус → 'verification', если gpVol==scVol то `acceptedVolume=scVol`
4. `closePeriod(periodId, actorId)` → вызывает `calcReadiness()` внутри транзакции → создаёт `readinessSnapshot`

**E-01:** 1 item, planVolume=100 (factory default), fact=70 → pct=70%
**E-02:** 1 item, fact=150 > plan=100 → pct capped at 100%
**E-03:** 3 items, contractValues=[30,50,20] → weightCoef=[0.30, 0.50, 0.20] (DB trigger), facts=[100, 50, 0] → readiness=55.0

Нужно разобраться, есть ли триггер в БД:

```bash
docker exec ccip_postgres psql -U ccip_admin -d ccip_dev -c "SELECT trigger_name FROM information_schema.triggers WHERE event_object_table='boq_items';"
```

Если триггер есть но weightCoef=null — значит trigger не вызывается при Prisma upsert. Это отдельный баг, не блокирующий W2.

**Если E-03 падает из-за weightCoef=null — временный фикс только для теста:**
После `makeBoQ`, вручную обновить weightCoef:
```typescript
const total = boq.items.reduce((sum, i) => sum + Number(i.contractValue), 0);
for (const item of boq.items) {
  await prisma.boqItem.update({
    where: { id: item.id },
    data: { weightCoef: Number(item.contractValue) / total },
  });
}
```
